# Task 39: Idempotent Workload Execution Handler

Status: In Progress (CP/RP libraries, authenticated Agent, Resource Plane worker composition, partial-batch SQS adapter, bounded leased recovery, and default-off queue/schedule Terraform are implemented locally across Tasks 40 and 62–65. AWS deployment, live Lambda MicroVM validation, and the Task 61 image/network PoC remain pending). Priority: P0.

## Goal

Implement the short-lived dispatch, Resource Plane execution, and result/cleanup handlers specified by [ADR 0008](../docs/adr/0008-non-ec2-workload-runtime.md). Reuse checkout, redaction, and artifact interfaces, but split the current direct-DB Service into Control Plane orchestration and Resource Plane executor. Tasks 40 and 62–65 implement durable command acceptance, Lambda MicroVM controller/SDK adapter, authenticated Agent, worker/recovery composition, cancellation Outbox, cleanup/replay, and local fault/DB tests. AWS deployment, live Lambda MicroVM verification, and the Task 61 image/network PoC remain open. A valid queue message must never be treated as success merely because it decoded.

## Acceptance criteria

- PostgreSQL integration tests cover concurrent duplicate messages, duplicate after terminal state, cancellation before/during execution, crash/retry recovery, timeout, artifact failure, and Tenant mismatch.
- Scheduler message deletion occurs after durable attempt + dispatch Outbox (or terminal duplicate recognition); Resource Plane command deletion follows a recoverable acceptance checkpoint. Result deletion follows durable CP terminal/duplicate recognition. Never hold one receipt for 24 hours.
- Tests cover conditional-journal conflicts, cancel/launch races, stale generations, old-allocation cleanup gating before replacement, visibility renewal failure, batch size 1, and fake-clock 24-hour deadlines.
- Recovery tests verify bounded multi-page sweeps, per-attempt failure isolation, continuation at the page budget, and repeated-token rejection. A production schedule/lease and its alarms remain Task 40 deployment work.
- Log/artifact metadata transaction remains Tenant-scoped; object bytes are redacted before persistence.
- The handler works with injected checkout/executor/queue in tests and does not run untrusted commands on the host.
- Keep `HAKO_WORKLOAD_RUNS_ENABLED` disabled until the Task 40 Worker, queues, IAM, alarms, and runtime prerequisites are deployed and readiness smoke tests pass.
