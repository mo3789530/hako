# Task 45: Workspace Agent and Secret References

Current update: Workspace PTY is connected to the TLS WSS Gateway through a signed-Workspace-bound adapter; shell command/output, allowlisted loopback port-forward, and same-MicroVM PTY detach/reattach E2E pass. The Guest pins each PTY to the Hako user from the signed one-use Agent Ticket, rejects cross-user and concurrent attachments, and buffers up to 1 MiB of output while disconnected. CLI reconnect obtains a fresh authorized Hako Session and one-use Agent Ticket with bounded retries; terminal state is in-memory and does not survive Guest/MicroVM replacement. A separate one-use VS Code ticket and fixed `127.0.0.1:8081` Guest bridge connect through the Lambda MicroVM adapter. Non-interactive `hako exec` is wired through its dedicated API Session permission, Gateway route, one-use Guest Agent ticket, bounded process manager, and CLI result/exit handling. The private Agent reports a versioned heartbeat over its Unix socket. Root init renews a 30-second heartbeat lease every 10 seconds and validates the pinned Tenant/Workspace/Plane/MicroVM identity before every new Gateway request; lease expiry fails closed and a valid response restores service. This does not update Control Plane observed state. Local tests cover lease expiry/recovery, heartbeat identity/version, Guest execution, permission separation, ticket replay rejection, CLI output, and session revocation. After EFS identity binding, the unprivileged Guest Agent starts image-pinned ARM64 code-server, checks `/healthz` before readiness, and stops its process group during shutdown. The Gateway uses a journal-backed per-stream resolver to select the current allocation without process-local lifecycle registration. Deployed MicroVM connectivity, production key distribution, actual ARM64 image build, and MicroVM `/dev/pts` validation remain.

CLI timeout update: `hako exec` now accepts an explicit `--timeout` before the `--` command separator, bounded to 100 ms–5 min; omitted timeout preserves the 60-second Agent default. The duration is validated at the CLI and protocol boundaries. Focused parser tests cover valid forms and invalid/duplicate/out-of-range values. See [`Workspace CLI`](../docs/workspace-cli.md).

## Goal

The Workspace shell endpoint is now launched by
`hako-workspace-init` as a distinct unprivileged `hako-workspace-agent` after
the strict EFS mount hook succeeds. The root init gives it only the bound
Workspace/MicroVM identity, image-owned Gateway origin and public-key file, and
an inherited listener on a mode-0600 Unix socket. The `/run` hook waits for an
internal readiness probe; root proxies only `/v1/workspaces/...`, then stops
the child before unmount. Local supervisor tests cover this boundary. The
deployed Gateway and a real token/dialer connection, actual Podman/Lambda MicroVM image and `/dev/pts`
validation, and production key distribution remain open. See
[`Workspace Agent shell and PTY`](../docs/workspace-agent-shell.md).

Provide the in-MicroVM `hako-agent` protocol needed for lifecycle reporting and developer commands, without exposing provider credentials or long-lived access tickets.

## Work

- Define an authenticated, versioned agent control protocol and heartbeat/lease behavior.
- Keep AWS endpoint credentials short-lived and scope each token to the single bound MicroVM and agent port; never persist them in the journal or expose them in logs/API responses.
- Add a separate signed app-layer ticket because Lambda strips its reserved `X-aws-proxy-*` headers before forwarding to the guest. Bind the ticket to MicroVM, complete attempt identity, one operation, key ID, nonce, and expiry.
- Implement bounded exec, shell/PTY, process lifecycle, file transfer, service control, and cancellation with explicit resource and output limits.
- Keep Workload execution commands server-owned and fixed; do not accept arbitrary shell/argv from Repository input.
- Use Secret Manager references; fetch secrets only into the target process at runtime and redact outputs. Never persist plaintext into DSQL, image, EFS source tree, or logs.
- Add protocol compatibility/version handling, heartbeat loss behavior, and audit correlation IDs.

## Acceptance criteria

- Unit/integration tests cover authorization, PTY lifecycle, same-user disconnect/reconnect, cross-user and concurrent-attach rejection, process cleanup, oversized requests/output, malformed frames, and secret redaction.
- Agent listens only on private Runtime interfaces; no public SSH or service/database ports are introduced.
- Document image build, update/rollback, protocol compatibility, and secret rotation.
