# ADR 0004: 共通設定、ログ、エラー処理

- Status: Accepted
- Date: 2026-09-23

## Context

複数のGoプロセスで設定、構造化ログ、エラーの扱いがばらつくと、運用時の調査と共通処理の変更が難しくなる。

## Decision

- 設定値は環境変数から読み込み、起動時に検証する。Secret値を通常の設定dumpやログに含めない。
- 構造化ログには標準ライブラリの`slog`を使い、JSON形式を基本とする。request ID、tenant ID、workspace ID、operation IDなどは存在する範囲で構造化フィールドにする。
- エラーは`%w`で原因を保持して層を越えて返す。API境界で安定した公開エラーへ変換し、内部情報やSecretを利用者向け応答に含めない。
- 各プロセスは同じ共通実装を利用し、プロセス固有の設定・エラー分類は各サービス側で定義する。

## Consequences

- 追加依存を増やさず共通規約を始められる。
- 設定検証、ログ秘匿、API error mappingを各サービス実装時にこの規約へ沿って追加する。
