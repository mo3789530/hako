# Terraform modules: inputs, outputs, tags, and IAM

The repository currently has two shared Terraform modules and two development roots. Both modules require Terraform 1.12.1+ and AWS provider 5.x. The roots select accounts and regions through their provider configuration; credentials come from the normal AWS provider chain, never Terraform variables.

## Control Plane module

Source: `infra/terraform/modules/control-plane`.

Required inputs: `aws_region`, `api_lambda_zip_path`, `cognito_issuer_url`, and `cognito_user_pool_id`. Optional settings are `api_name` (`hako-control-plane`), `api_lambda_image_uri` (empty by default; immutable digest creates a separate container-image candidate), `api_lambda_image_active` (`false`; switches the API Gateway integration only after candidate validation), `dsql_deletion_protection_enabled` (`true`), `default_workspace_image` (`hako-dev:latest`), `default_workspace_runtime_class` (`standard`), API Lambda memory (1024 MiB), timeout (25 seconds), log retention (30 days), caller `tags`, CLI app client name (`hako-cli`), and OAuth callback URLs (localhost loopback). Callback URLs are restricted to HTTPS or local loopback HTTP. The module creates a private same-Region ECR repository with immutable tags, scan-on-push, Lambda-scoped retrieval permission, and seven-day cleanup for untagged images; tagged digests require deliberate cleanup after no Lambda/rollback reference remains. Its URL is exported as `api_lambda_ecr_repository_url`. API Gateway targets ZIP unless `api_lambda_image_active` is true. The Outbox Dispatcher execution role/log group are provisioned by default; its scheduled Lambda is opt-in through `enable_outbox_dispatcher` (default `false`), requires `dispatcher_lambda_zip_path` from `make build-dispatcher-lambda`, and accepts a validated version-1 `resource_plane_manifest_json`. Hako ownership tags (`hako:managed-by`, `hako:plane`) override caller-provided values.

Outputs include HTTP API ID/endpoint, Cognito authorizer ID/scope/client ID, DSQL cluster ARN/endpoint, API Lambda ARN/role ARN, the separate DSQL migration-admin policy ARN, Dispatcher role ARN, and nullable Dispatcher Lambda/schedule/error-alarm identifiers. Sensitive credentials are not output.

All tagged resources receive `hako:managed-by=hako` and `hako:plane=control`. API runtime IAM is limited to log stream/event writes on its pre-created log group and `dsql:DbConnect` on this DSQL cluster. The migration policy separately grants only `dsql:DbConnectAdmin` on that cluster and is not attached to a principal by the module. The Dispatcher role gets log writes, `dsql:DbConnect`, and—only when enabled—`sqs:SendMessage` to the queue ARNs derived from the validated manifest. The optional GitHub Webhook Processor has a separate role limited to log writes and `dsql:DbConnect`. Both scheduled Lambdas use one-minute EventBridge schedules, bounded retries, and Errors alarms. API Gateway is granted invoke permission only from this API. The module does not own the User Pool or provision a separate Outbox queue, Scheduler, Reconciler, or Result Consumer infrastructure.

## Resource Plane module

Source: `infra/terraform/modules/resource-plane`.

Required inputs: `resource_plane_id`, `control_plane_dispatcher_role_arn`, and `control_plane_result_consumer_role_arn`. Optional settings tune the command and result visibility timeouts (6000 seconds each), primary/DLQ message retention (4/14 days), maximum receives (5), log retention (30 days), alarm thresholds (300 seconds oldest age, 100 visible messages), and SNS alarm actions (empty by default). `tags` adds caller-provided tags. The development-only fake controller is disabled by default; enabling it requires the built arm64 ZIP and accepts Lambda timeout, execution timeout, and memory settings.

Outputs expose each command/result queue and DLQ URL/ARN, controller role and log group, monitoring alarm names, plus nullable fake Lambda ARN, event-source mapping UUID, and log group. Required tags are `hako:managed-by=hako` and `hako:resource-plane-id=<id>`; queue role tags identify commands, results, DLQs, and fake-only resources.

The cross-account queue policy allows the exact Dispatcher role to send only to the command queue and the exact Result Consumer role to receive/delete/change visibility only on the result queue. The controller role consumes commands, publishes results, and writes to its own log groups; it has no DSQL, general AWS resource management, or cross-account assume-role permissions. See [`resource-plane-queues-and-dlq.md`](resource-plane-queues-and-dlq.md) for redrive and failure operations.

## Environment differences and deployment order

`environments/dev/control-plane` creates the Control Plane account resources; its Cognito User Pool is externally managed and its ZIP Lambda package must first be built with `make build-api-lambda`. The optional image candidate uses `make build-api-lambda-image`; publish it to the module-managed ECR repository from an authorized release environment and supply the immutable image digest as `api_lambda_image_uri`. Keep `api_lambda_image_active=false` while directly invoking and validating the candidate; set it true only for a separately reviewed promotion. The DSQL cluster has deletion protection on by default. `environments/dev/resource-plane` creates the queue/controller foundation in the Resource Plane account; it does not enable the fake Lambda unless explicitly requested with `enable_fake_resource_controller = true`. The account boundary is selected by the AWS credentials/profile used for each root. There is no staging or production root and no root performs `apply` in CI. Apply only after reviewing the account identity and plan.

For an initial cross-account rollout, provision Control Plane identity/roles, configure their exact ARNs in the Resource Plane root, and then register the resulting queue URLs/region in the Control Plane manifest. DSQL role mapping and SQL migrations are a separate operator step documented in [`control-plane-terraform.md`](control-plane-terraform.md).
