# Terraform modules: inputs, outputs, tags, and IAM

The repository currently has four Terraform modules and two development roots. The modules require Terraform 1.12.1+ and AWS provider 5.x. The roots select accounts and regions through their provider configuration; credentials come from the normal AWS provider chain, never Terraform variables.

## Control Plane module

Source: `infra/terraform/modules/control-plane`.

Required inputs: `aws_region`, `api_lambda_zip_path`, `cognito_issuer_url`, and `cognito_user_pool_id`. Optional settings are `api_name` (`hako-control-plane`), `api_lambda_image_uri` (empty by default; immutable digest creates a separate container-image candidate), `api_lambda_image_active` (`false`; switches the API Gateway integration only after candidate validation), `dsql_deletion_protection_enabled` (`true`), `default_workspace_image` (`hako-dev:latest`), `default_workspace_runtime_class` (`standard`), API Lambda memory (1024 MiB), timeout (25 seconds), log retention (30 days), caller `tags`, CLI app client name (`hako-cli`), and OAuth callback URLs (localhost loopback). Callback URLs are restricted to HTTPS or local loopback HTTP. The module creates a private same-Region ECR repository with immutable tags, scan-on-push, Lambda-scoped retrieval permission, and seven-day cleanup for untagged images; tagged digests require deliberate cleanup after no Lambda/rollback reference remains. Its URL is exported as `api_lambda_ecr_repository_url`. API Gateway targets ZIP unless `api_lambda_image_active` is true. The Outbox Dispatcher execution role/log group are provisioned by default; its scheduled Lambda is opt-in through `enable_outbox_dispatcher` (default `false`), requires `dispatcher_lambda_zip_path` from `make build-dispatcher-lambda`, and accepts a validated version-1 `resource_plane_manifest_json`. GitHub Checks delivery is separately opt-in through `enable_github_checks_delivery` (default `false`, requires the Dispatcher); it configures an encrypted standard queue, 14-day DLQ/redrive after five receives, bounded visibility timeout, dedicated ECS/Fargate task role and queue policy, DSQL-connect policy, and queue age/depth/DLQ alarms. Optional `github_checks_alarm_actions` supplies SNS topics for alarm and OK notifications. `enable_github_checks_consumer_service` separately opts in to an ARM64 Fargate service/task with private subnet attachment, a digest-pinned image, and explicit Secrets Manager references for broker mTLS. It requires a pre-created ECS cluster, security groups/subnets, broker URL and three provisioned Secret ARNs; it defaults off and does not fetch Secrets during planning. Hako ownership tags (`hako:managed-by`, `hako:plane`) override caller-provided values.

The Control Plane also exports a stable `workspace_idle_reconciler_role_arn` so the operator can map the dedicated DSQL role before enabling the feature. `enable_workspace_idle_reconciler` defaults to `false`; when enabled, the module requires the ARM64 ZIP from `make build-workspace-idle-reconciler-lambda`, grants only DSQL `DbConnect` and scoped log writes, and creates a scheduled EventBridge rule (default `rate(1 minute)`) plus a Lambda Errors alarm. `workspace_idle_reconciler_batch_size` is bounded to 1–1000. The separate DSQL `hako_workspace_idle_reconciler` SQL grants are in the bootstrap template. No tenant policy is auto-enabled by Terraform. The separate `enable_preview_expiry_reconciler` schedule also defaults to `false`; it requires the ARM64 ZIP from `make build-preview-expiry-lambda`, the stable `preview_expiry_reconciler_role_arn` mapping, and the `hako_preview_reconciler` SQL grants. Its DbConnect/log policy and one-minute EventBridge/Lambda Errors alarm are scoped to the metadata expiry sweep, which only moves rows to `cleanup_pending`; it does not remove runtime resources. The batch is bounded to 1–500. No AWS apply is performed.

Outputs include HTTP API ID/endpoint, Cognito authorizer ID/scope/client ID, DSQL cluster ARN/endpoint, API Lambda ARN/role ARN, the separate DSQL migration-admin policy ARN, Dispatcher role ARN, nullable Dispatcher Lambda/schedule/error-alarm identifiers, stable Checks task role ARN, nullable Checks execution role/service/task-definition ARNs, queue/DLQ URLs, consumer policy ARN, queue/DLQ alarm names, the stable Workspace idle reconciler role ARN, and nullable idle Lambda/schedule/error-alarm identifiers. Sensitive credentials are not output.

All tagged resources receive `hako:managed-by=hako` and `hako:plane=control`. API runtime IAM is limited to log stream/event writes on its pre-created log group and `dsql:DbConnect` on this DSQL cluster. The migration policy separately grants only `dsql:DbConnectAdmin` on that cluster and is not attached to a principal by the module. The Dispatcher role gets log writes, `dsql:DbConnect`, and—only when enabled—`sqs:SendMessage` to the queue ARNs derived from the validated manifest and optional Checks queue. The ECS Checks task role gets only `dsql:DbConnect` on this cluster and receive/delete/change-visibility/queue-attribute actions on the dedicated Checks queue. Its SQL role is separately mapped/granted by the operator bootstrap. The optional GitHub Webhook Processor has a separate role limited to log writes and `dsql:DbConnect`. Scheduled Lambdas use one-minute EventBridge schedules, bounded retries, and Errors alarms; Checks queue alarms can notify configured SNS topics. API Gateway is granted invoke permission only from this API. The module does not own the User Pool or provision a Scheduler, Reconciler, Result Consumer runtime, or Resource Plane queues.

Tenant-owned GitHub private-key access and Claude/model credentials are separate from API Webhook-secret access and from each other. The optional `github_broker_role_name`, `tenant_github_private_key_reader_role_arns`, and `tenant_model_credential_reader_role_arns` inputs call the [`github-broker-tenant-iam` module](../infra/terraform/modules/github-broker-tenant-iam/README.md), attaching purpose-specific policies containing only `sts:AssumeRole` to exact reader ARNs on the existing broker role. Model credential Roles must use `role/hako/tenant-model-credential-reader/`; private-key Roles use `role/hako/tenant-private-key-reader/`. Empty inputs create no policy, wildcard/wrong-purpose ARNs are rejected, and Terraform rejects reuse among model credential, private-key, and API Webhook reader purposes. The reusable [`tenant-model-credential-reader-role` module](../infra/terraform/modules/tenant-model-credential-reader-role/README.md) configures one exact Broker trust, one Secret read, and optional context-scoped KMS decrypt. Secret provisioning, cross-account Secret resource policies, and broker certificate provisioning remain operator-managed; no Secret value is read during plan.

## Resource Plane module

Source: `infra/terraform/modules/resource-plane`.

Required inputs: `resource_plane_id`, `control_plane_dispatcher_role_arn`, and `control_plane_result_consumer_role_arn`. Optional settings tune the command and result visibility timeouts (6000 seconds each), primary/DLQ message retention (4/14 days), maximum receives (5), log retention (30 days), alarm thresholds (300 seconds oldest age, 100 visible messages), and SNS alarm actions (empty by default). `tags` adds caller-provided tags. The development-only fake controller is disabled by default; enabling it requires the built arm64 ZIP and accepts Lambda timeout, execution timeout, and memory settings. The Workspace `workspace_runtime_deployment` also defaults to `null`; when supplied with a built ARM64 Resource Controller ZIP (`make build-resource-controller-lambda`), exact S3 journal bucket/prefix, pinned image/version, fixed network profile, and dynamic EFS Workspace roles, it creates one Lambda MicroVM controller and one batch-size-1 partial-failure command-queue mapping. Fake and MicroVM controllers are mutually exclusive because they consume the same queue. Its IAM is scoped to the exact MicroVM image, exact journal object prefix, and optional journal CMK; it has no S3 listing or deletion permission. `lambda:ConnectMicrovm` and `lambda:PassNetworkConnector` require `Resource: "*"` under the [AWS Lambda Service Authorization Reference](https://docs.aws.amazon.com/service-authorization/latest/reference/list_lambda.html), so the profile is fixed and the execution role is dedicated to this controller. Leave this input `null` until the Task 44/45/61 image, agent, storage, network, and lifecycle gates are reviewed; no Workspace Runtime is enabled by the dev root. Separate Workload command and result queues/DLQs are opt-in through `enable_workload_result_queue` (default `false`) and require the exact Control Plane Workload result consumer role ARN. They create independent redrive/age/backlog alarms and a Workload Controller IAM role; the role consumes only the dedicated Workload command queue, sends only to the Workload result queue, and writes to its own pre-created logs. `workload_controller_runtime` defaults to `null`; when explicitly configured, it requires six unique concrete runtime Secret ARNs and adds `GetSecretValue` only for those ARNs, `Run/Get/Terminate/CreateAuthToken` only for one exact MicroVM image, S3 actions only for the configured journal/source/artifact prefixes and exact recovery-lease object, and optional KMS use for exact source/artifact keys and configured Secret CMKs. No Secret values are Terraform inputs. `workload_controller_deployment` defaults to `null`; when configured it requires the dedicated queue and runtime policy plus an existing Worker ZIP, HTTPS API/broker endpoints, matching six named Secret ARNs, runtime profiles, bounded recovery and cleanup parameters, and a queue visibility timeout at least six times the Lambda timeout. It creates one ARM64 combined-mode Lambda, a batch-size-1 `ReportBatchItemFailures` mapping for only the Workload command queue, a bounded EventBridge recovery and Artifact cleanup schedules, and Lambda/EventBridge invocation alarms. Function, mapping, and schedule outputs are null unless opted in. This deployment contract does not provision Secret values, VPC/NAT/endpoint routes, KMS key policies, broker certificates/allowlists, MicroVM images, or live network isolation; those remain review/verification gates. The exact Dispatcher role alone can send to the Workload queue. The Workspace Operation queues remain separate.

Outputs expose each command/result queue and DLQ URL/ARN, controller role and log group, monitoring alarm names, plus nullable fake Lambda ARN, event-source mapping UUID, and log group. Dedicated Workload command/result queue/DLQ URLs and ARNs, minimal Workload Controller role ARN, and its log group are null unless opted in. Worker Lambda ARN, command mapping UUID, and recovery schedule ARN are additionally null until `workload_controller_deployment` is configured. Required tags are `hako:managed-by=hako` and `hako:resource-plane-id=<id>`; queue role tags identify commands, Operation results, Workload queues, DLQs, and fake-only resources.

The opt-in Workload deployment also schedules bounded Artifact cleanup on the same Resource Plane Lambda. Cleanup uses the signed Resource Plane-scoped Control Plane API and grants `s3:DeleteObject` only for the configured Artifact object prefix. Its schedule, maximum batch size, and EventBridge invocation alarm are explicit configuration/outputs. Leave `workload_artifact_storage` null for an externally managed bucket; Terraform does not take ownership implicitly. No `apply` is performed by local plan tests.

`workload_artifact_storage` optionally provisions the configured artifact bucket with BucketOwnerEnforced ownership, all public-access blocks, versioning, default SSE-S3 or the configured artifact KMS key, TLS-only transport, and a narrow Controller-role grant for Put/Delete under the exact artifact prefix. Current/noncurrent version retention, expired-delete-marker cleanup, and incomplete multipart cleanup are configured. Bucket ARN/name outputs remain null when disabled; existing buckets must be imported and reviewed before managed mode is enabled. The bucket is not force-destroyed.

The combined Resource Plane Lambda now reads a sixth, dedicated Artifact-cleanup HMAC Secret. It is distinct from the execution-metadata HMAC key, broker mTLS material, and Agent ticket key; IAM grants secret-read only to the six exact configured ARNs. The cleanup schedule remains opt-in with the entire Workload Controller deployment.

The scheduled health reporter and its alarms are separately opt-in (`enable_health_reporter=false`, `enable_health_report_alarms=false`). Enabling the reporter requires its ARM64 zip, Control Plane HTTPS origin, exact Plane HMAC Secret ARN, immutable MicroVM image ARN/version, VPC connector ARN, exact unqualified Controller Lambda function ARN, exact EFS filesystem ARN, and alarms. It checks queue metadata, MicroVM image/connector state, Controller function state, and EFS filesystem metadata; it does not prove message processing, a successful MicroVM launch, egress policy, or EFS mounting from a Workspace. Its role is limited to the exact Secret, queue ARNs, image/connector/Controller/EFS ARNs, and retained log stream. Planning does not retrieve Secret values; provisioning paired HMAC keys and validating runtime alarms remain operator tasks. The development root leaves these features disabled by default.

`workspace_service_controller_deployment` and its VPC configuration default to `null`. Setting them explicitly creates an encrypted dedicated Workspace Service queue/DLQ, exact Dispatcher send policy, private ARM64 Lambda MicroVM consumer, SQS partial-batch mapping, minimal journal/Secrets/MicroVM IAM policy, retained logs, and DLQ/age/Lambda error alarms. It requires the built ZIP, two distinct exact Secret ARNs, ticket key ID, exact image ARN, journal bucket/prefix, HTTPS Control Plane endpoint, and pre-created private subnet/security group IDs. Outputs are nullable until enabled. The dev root forwards these values. It does not create network endpoints/routes, retrieve Secret values, install the Workspace container runtime, or apply infrastructure. Its `ec2:*` permissions are only Lambda VPC ENI plumbing; EC2 is not a Workspace runtime.

`workspace_gateway_deployment` defaults to `null`. When configured, it creates a public HTTPS-only ALB on port 443 with a 60-minute idle timeout for long-lived WebSockets, forwarding TLS to an ARM64 Fargate service in private subnets, with no public task IP, Execute Command, deployment rollback, CPU scaling, target-health and ALB 5xx alarms. The Gateway image must be a digest-pinned ECR image in this Resource Plane account/Region; the AWS CLI secret-loader image must also be pinned by digest. Runtime IAM is limited to the exact MicroVM image, Resource Plane journal prefix, and six configured Secret ARNs (TLS certificate/key, Session public keys, separate Session-lookup and connection-lease HMAC keys, Agent-ticket private key), plus optional exact CMKs constrained by Secrets Manager encryption context. The sidecar writes SecretString data to an ephemeral shared volume; the Gateway container mounts it read-only as UID 65532. This module does not put Secret values in Terraform inputs/state or task environment. ECS shares one task role between containers, so the Gateway task role also has the same six exact `GetSecretValue` permissions. Public/private subnet routing, DNS, ACM certificate issuance, Secret/KMS resource policies, and HTTPS egress destinations are operator-provisioned. Outputs include the configured public origin, ALB DNS name, service/task-role/ALB ARNs, and alarm names. The feature remains disabled by default and mock-plan tests do not apply resources or retrieve Secrets.

## Workspace storage module

Source: `infra/terraform/modules/workspace-storage`, optionally wired through the dev Resource Plane root's nullable `workspace_storage` input. It requires a stable `resource_plane_id`, VPC ID, at least two private subnet IDs, and exact Lambda MicroVM connector security group IDs. Static mode (default) requires exact Workspace runtime role/AP pairs. Explicit dynamic mode allows only the `/hako/workspaces/` IAM role path and same-account/Region EFS Access Points over TLS; each generated role has a one-AP identity policy with explicit denies. An explicit identity deny is necessary because same-account identity/resource policy allows combine. The module creates encrypted general-purpose EFS, private mount targets, connector-only TCP/2049 ingress, and daily AWS Backup recovery points (35-day default). It does not create Access Points or per-Workspace roles. Outputs expose filesystem, mount-target security group/IDs, and backup vault/plan IDs.

The module does not create Access Points, per-Workspace IAM roles, VPC/subnets, or Lambda MicroVM network connectors. The Resource Controller now contains local dynamic role provider/runtime wiring, but Resource Plane Terraform does not yet grant its IAM lifecycle/PassRole permissions. Caller-provided subnet privacy, distinct AZs, actual IAM enforcement, EFS mount success, and connector compatibility remain unverified. Keep runtime creation disabled until these deployment and live-isolation gates pass. Mock tests do not contact AWS or apply infrastructure.

The Control Plane Workload execution-metadata route is disabled unless `resource_plane_workload_spec_secret_arns` maps Resource Plane IDs to dedicated exact Secrets Manager ARNs. It creates a throttled API Gateway `NONE` route and grants the API role `GetSecretValue` only for those ARNs; Terraform rejects ARNs also used for health reporting. Requests are HMAC-authenticated by Resource Plane ID, and the handler revalidates the Run/attempt/App binding before returning non-secret metadata. Planning does not retrieve Secret values, and the dev root defaults to an empty map. Enabling the route does not deploy or enable a Workload worker.

The cross-account queue policies allow the exact Dispatcher role to send only to Workspace and (when enabled/configured) Workload command queues, the exact Workspace Operation result consumer role to consume only that result queue, and the exact Workload result consumer role to consume only the dedicated Workload result queue. The Workspace Resource Controller role remains limited to Workspace commands, Operation results, and its log group. The optional Workload runtime policy is opt-in separately from queues; it contains the exact image, attempt-prefix S3/KMS, recovery-lease, and Secret scopes described above. It still does not grant broker access, attach a Lambda/event source, provision VPC endpoints, or prove live permissions. See [`resource-plane-queues-and-dlq.md`](resource-plane-queues-and-dlq.md) for redrive and failure operations.

### Resource Plane deployment plan tests

`make terraform-test` initializes the Resource Plane, Workspace Storage, GitHub Broker Tenant IAM, and Tenant model credential reader Role modules and runs mock-provider plan tests. They assert that the Workspace MicroVM, Workload, and Workspace Service Lambdas, command mappings, recovery schedules, and runtime IAM remain absent by default; validate the Workspace MicroVM opt-in ZIP/profile, exact image and S3 object permissions, absence of S3 list/delete access, queue exclusivity, and dynamic EFS role requirement; validate Workload wiring and exact queue/Secret/MicroVM permissions; and verify the broker-only exact private-key and model-credential reader allowlists, target-role trust/Secret/KMS scope, default-off behavior, and purpose separation. The plan tests do not call AWS APIs or apply resources. The integration test also verifies that a dotted recovery lease key such as `lease.json` is accepted while `..` is rejected by the Terraform variable contract.

## Environment differences and deployment order

`environments/dev/control-plane` creates the Control Plane account resources; its Cognito User Pool is externally managed and its ZIP Lambda package must first be built with `make build-api-lambda`. The optional image candidate uses `make build-api-lambda-image`; publish it to the module-managed ECR repository from an authorized release environment and supply the immutable image digest as `api_lambda_image_uri`. Keep `api_lambda_image_active=false` while directly invoking and validating the candidate; set it true only for a separately reviewed promotion. The DSQL cluster has deletion protection on by default. `environments/dev/resource-plane` creates the queue/controller foundation in the Resource Plane account; it does not enable the fake Lambda unless explicitly requested with `enable_fake_resource_controller = true`. The account boundary is selected by the AWS credentials/profile used for each root. There is no staging or production root and no root performs `apply` in CI. Apply only after reviewing the account identity and plan.

For an initial cross-account rollout, provision Control Plane identity/roles, configure their exact ARNs in the Resource Plane root, and then register the resulting queue URLs/region in the Control Plane manifest. DSQL role mapping and SQL migrations are a separate operator step documented in [`control-plane-terraform.md`](control-plane-terraform.md).
